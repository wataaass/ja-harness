# エージェントの往復と文脈管理の設計（v0.1）

## 往復（エージェントループ）
1. 指示・道具の定義・会話をモデルに送る
2. モデルが道具を呼んだら、モード（`ui.md`）に沿って確認してから実行し、結果を会話に足す
3. モデルが道具を呼ばずに答えたら、1回のやりとりを終える
4. 1回のやりとりの往復が **30回** を超えたら止めて、続けるかを利用者に聞く（安いモデルが同じことをくり返すのを防ぐ）

## 会話の並べ方（キャッシュを効かせる）
`[指示][道具の定義][会話…]` の順にし、先頭は毎回同じにする。会話はうしろに足していくだけにする。先頭が同じなら、その部分はキャッシュ（同じ入力の再利用）で安く読まれる。

過去の会話を書き換える（隠す・要約する）と、そこから先のキャッシュが効かなくなる。そのため書き換えは、しきい値を超えたときにまとめて1回で行う。

## トークンを抑える仕組み
| 仕組み | 既定値（推奨値） | 動き |
| --- | --- | --- |
| 道具の結果の上限 | 1件 2,000トークン | 超えたら、大事な行（エラー、一致した行）を先に、残りは先頭と末尾を残して「ほかN行」と書く。ファイルは行の範囲を指定して続きを読める |
| observation masking | 最初から常に。直近10件を残す | rolling window の外に出た道具の結果を、パスやコマンドを残した1行（例「src/a.ts を読んだ。120行。必要なら読み直す」）に置き換える（restorable） |
| masking の頻度 | window の外に10件たまったら、まとめて1回 | 毎ターン書き換えると KV-cache が崩れるので、書き換えはまとめて行う |
| 古くなった読み取り | すぐ隠す | 編集したファイルの、編集より前の読み取り結果は、window の中でも隠す（最新の中身だけを残す） |
| LLM-Summary | 文脈が 32Kトークン、またはモデルの上限の70%の小さいほうを超えたら | 古い会話をモデルに要約させて置き換える。要約には masking する前の会話を渡す。`/compact` で手動でも実行できる |
| 道具の定義は必要なときだけ | MCP の道具 | 組み込みの道具は少数に絞る。MCP の道具は名前と一言だけを見せ、使うときに詳しい定義を読ませる |
| 往復の上限 | 30回で確認 | 超えたら止めて、続けるかを聞く |
| 使った量を見せる | 常に | 状態の行に文脈の割合・トークン・料金、`/context` で内訳 |

## 設定
上の値はすべて設定ファイルで変えられる。作業フォルダの `.ja-harness/config.json` が、ホームの `~/.ja-harness/config.json` より優先される。

```json
{
  "context": {
    "toolResultMaxTokens": 2000,
    "masking": { "enabled": true, "keepRecent": 10, "batch": 10, "maskStaleReads": true },
    "summary": { "maxTokens": 32000, "maxRatio": 0.7 },
    "maxTurns": 30
  }
}
```

`masking.enabled` を false にし、`summary.maxRatio` だけで動かせば、「上限の70%で初めて手を入れる」形（Claude Code などに近い）にもできる。測定で両方を比べられるようにするため。

## 根拠
- 道具の結果の上限: 上限を1,000〜8,000トークンの4段階で比べた研究で、大事な項目を先頭に並べれば1,000トークンでも必要な項目が先頭に来る割合は変わらず、エージェントは2ページ目をまったく取りに来なかった（Agents Don't Paginate、arXiv 2608.26130）。Claude Code は 10,000トークンで警告し、25,000で切る
- masking を常に動かす: observation masking は rolling window（M=10）で最初から動かし、要約と同じくらい解けて費用は約半分だった。短い trajectory でも効き、トークンの約84%は道具の結果だった（The Complexity Trap、NeurIPS 2025、arXiv 2508.21433）
- 要約は最後の手段: 同じ研究の hybrid（masking を常に動かし、約30Kトークンで LLM-Summary）は、masking だけより費用が7%少なく、解けた割合は2.6pt 高かった。要約の呼び出しはキャッシュが効かず高い。パラメータを雑に組み合わせると逆に悪化した
- 長くしすぎない: 18モデルで、入力が長くなるほど性能が不安定になった（Context Rot、Chroma 2025）
- KV-cache: prefix を固定し、context は append-only にすると hit rate が上がる。圧縮は、パスや URL を残して restorable にする（Manus、Context Engineering for AI Agents）。tool result clearing は最も安全で軽い compaction（Anthropic、Effective context engineering for AI agents）
- 古くなった読み取り: Complexity Trap は限界として、window が古さを見ない（ファイルを変更したあとも古い中身を残す）ことを挙げている。すぐ隠すのは、この指摘からの推論で、測定で確かめる
- まとめて隠す頻度（10件）は、masking と KV-cache を両立させるための推論で、論文が直接示した値ではない。測定で見直す

## まだ決めていないこと
- 推奨値のうち、論文にない値（まとめて隠す10件、要約の32K、古い読み取りをすぐ隠す）は、測定の仕組み（次の版）ができたら見直す
- 道具の結果を「大事な順」に並べる方法（コマンドごとに決めるか、汎用の規則にするか）
