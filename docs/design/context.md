# エージェントの往復と文脈管理の設計（v0.1）

## 往復（エージェントループ）
1. 指示・道具の定義・会話をモデルに送る
2. モデルが道具を呼んだら、モード（`ui.md`）に沿って確認してから実行し、結果を会話に足す
3. モデルが道具を呼ばずに答えたら、1回のやりとりを終える
4. 1回のやりとりの往復が **30回** を超えたら止めて、続けるかを利用者に聞く（安いモデルが同じことをくり返すのを防ぐ）

## 会話の並べ方（キャッシュを効かせる）
`[指示][道具の定義][会話…]` の順にし、先頭は毎回同じにする。会話はうしろに足していくだけにする。先頭が同じなら、その部分はキャッシュ（同じ入力の再利用）で安く読まれる。

過去の会話を書き換える（隠す・要約する）と、そこから先のキャッシュが効かなくなる。そのため書き換えは、しきい値を超えたときにまとめて1回で行う。

## トークンを抑える仕組み
| 仕組み | 既定値 | 動き |
| --- | --- | --- |
| 道具の結果の上限 | **1件 2,000トークン** | 超えたら、大事な行（エラー、一致した行）を先に、残りは先頭と末尾を残して「ほかN行」と書く。ファイルは行の範囲を指定して続きを読める |
| 古い道具の結果を隠す | 文脈が **モデルの上限の70%** を超えたら | 直近 **10件** の道具の結果だけを残し、それより古いものを1行（例「src/a.ts を読んだ。120行」）に置き換える。編集中のファイルは、件数に関係なく最新の中身を残す |
| 会話の要約 | 隠しても70%を超えるとき | 古い会話をモデルに要約させて置き換える。要約は1回ぶんの費用がかかり、細部が抜けるので最後の手段にする。`/compact` で手動でも実行できる |
| 道具の定義は必要なときだけ | MCP の道具 | 組み込みの道具は少数に絞る。MCP の道具は名前と一言だけを見せ、使うときに詳しい定義を読ませる |
| 使った量を見せる | 常に | 状態の行に文脈の割合・トークン・料金、`/context` で内訳 |

どの値も設定で変えられる。

## 根拠
- 結果の上限: 道具の結果の上限を1,000〜8,000トークンの4段階で比べた研究で、大事な項目を先頭に並べれば、1,000トークンでも必要な項目が先頭に来る割合は変わらなかった。エージェントは2ページ目をまったく取りに来なかった（Agents Don't Paginate、arXiv 2608.26130）。Claude Code は 10,000トークンで警告し、25,000で切る
- 隠す件数: 古い観察を隠す方法は、要約と同じくらい解けて費用は約半分だった。残す数は10が本線の設定（The Complexity Trap、NeurIPS 2025、arXiv 2508.21433）。最適な数はエージェントによって違うので、測定で見直す
- 出典は wataaass/nihongo-kit の `docs/research/imozuru-token/map.md` にまとめてある

## まだ決めていないこと
- モデルの上限の70%は、128kトークンのモデルでは約9万トークンになる。隠し始めが遅いぶん、それまでの往復は高くつく。測定の仕組み（次の版）ができたら、より小さい固定の予算と比べて見直す
- 道具の結果を「大事な順」に並べる方法（コマンドごとに決めるか、汎用の規則にするか）
